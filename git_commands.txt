STEP 1 - LOCAL REPOSITORY SETUP
--------------------------------------------------------------------------
mkdir "SDP SGA 2"
    Makes the project folder inside /Users/vaibhavbarman/.
cd "SDP SGA 2"
    Goes into that folder so every later command runs there.
ls -la
    Lists everything in the folder, hidden files too. I used it to check that index.html and about.html were there.
git --version
    Prints the Git version, a quick check that Git is installed.
git init -b main
    Turns the folder into a Git repository and names the first branch main.
git config user.name "Vaibhav Barman"
    Sets the name Git writes as the author on my commits, for this repository only.
git config user.email "181400932+vaibhav-barman@users.noreply.github.com"
    Sets the author email to my GitHub no-reply address so my real email stays out of the public history.
git status
    Reports what Git sees right now: untracked, modified and staged files.

STEP 2 - GIT WORKFLOW EXECUTION
--------------------------------------------------------------------------
git add index.html about.html
    Puts both pages in the staging area so the next commit includes them.
git status --short
    Short version of status. An "A" in the first column means the file is staged as new.
git commit -m "Initial commit: add index.html and about.html"
    Saves the staged pages as the first commit, the starting state of the project.
git diff
    Shows the exact lines I changed but have not staged yet. I ran it before each commit to review the edit.
git add index.html
    Stages the edited index.html.
git commit -m "Update index.html: add paragraph about version control"
    Saves the index.html edit as the second commit.
git branch feature
    Creates a branch called feature at the current commit. It does not move me onto it.
git branch
    Lists the local branches and puts a * next to the one I am on.
git checkout feature
    Moves me onto the feature branch.
git add about.html
    Stages the edited about.html.
git commit -m "Feature: add skills list to about.html"
    Saves the about.html edit on the feature branch only, so main does not have it yet.
git log --oneline --graph --all --decorate
    Prints the history as a small graph, one line per commit, covering every branch and showing where HEAD is.
git checkout main
    Moves me back to main. about.html changes back to the version without the skills list.
git merge --no-ff feature -m "Merge branch feature into main"
    Brings the feature work into main. --no-ff makes Git record a merge commit, so the branch stays visible in the log.
git log --stat
    Prints each commit in full along with the files it touched and how many lines were added or removed.

STEP 3 - .gitignore IMPLEMENTATION
--------------------------------------------------------------------------
printf '# Ignore log files\n*.log\n\n# Ignore the temp folder\ntemp/\n' > .gitignore
    Writes the .gitignore file with two rules: skip every .log file and skip the temp/ folder.
echo "debug output" > app.log
    Makes a sample log file to test the first rule.
mkdir -p temp && echo "cache data" > temp/cache.txt
    Makes a temp/ folder with a file in it to test the second rule.
cat .gitignore
    Prints the .gitignore file to confirm what is in it.
git status --ignored --short
    Also lists ignored items, marked with "!!". app.log and temp/ show up this way.
git check-ignore -v app.log temp/cache.txt
    Tells me which line of .gitignore matched each path.
git add .gitignore
    Stages the .gitignore file.
git commit -m "Add .gitignore to ignore .log files and temp/ folder"
    Saves .gitignore as its own commit.

STEP 4 - UNDO OPERATION
--------------------------------------------------------------------------
git commit -m "Add experimental banner (will be undone)"
    An extra commit (after editing and staging index.html) that exists only so I can undo it.
git reset --hard HEAD~1
    Moves the branch back one commit and throws away that commit's changes in the working files. This is the undo.
git reflog -5
    Shows the last five places HEAD pointed to. The reset is listed there, and so is the commit it removed.
git commit -m "Add draft footer note (will be reverted)"
    A second throwaway commit, this time for trying the other undo method.
git revert HEAD --no-edit
    Undoes the last commit by adding a new commit that reverses it. History stays intact, which is safer for shared branches.

STEP 5 - GITHUB INTEGRATION
--------------------------------------------------------------------------
git add git_commands.txt
    Stages this documentation file.
git commit -m "Add git_commands.txt documenting all Git commands used"
    Saves the documentation file in the repository.
(GitHub website) New repository -> name "sdp-sga2-git-workflow" -> Public -> leave README, .gitignore and licence unticked
    Creates the empty public repository on GitHub, done only after the local repository already had its history.
git remote add origin https://github.com/vaibhav-barman/sdp-sga2-git-workflow.git
    Links my local repository to the GitHub one under the name origin.
git remote -v
    Lists the remotes and their URLs so I can check the link.
git push -u origin main
    Uploads main with all its commits and remembers origin/main as its upstream.
git push origin feature
    Uploads the feature branch too, so the branch work shows on GitHub.
git branch -vv
    Lists each local branch with its latest commit and the remote branch it follows.
git log --oneline --graph --all --decorate
    Last look at the history, now including the origin/* branches, to compare with GitHub.
git add git_commands.txt
    Stages this file again after I reworded the explanations.
git commit -m "Reword explanations in git_commands.txt"
    Saves the reworded version as a new commit.
git push
    Uploads that last commit to GitHub.
